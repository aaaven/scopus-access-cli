# 0.4.2：保留较小余额并继续

0.4.1 的错误是把可保守合并的有效同窗口数值差异当成未知额度，并因此暂停。
补足错误显示没有解决这个问题。0.4.2 在真实响应的对账事务中自动取较小值，
无需证明上游计费时序，也没有硬编码一请求容差。

## 余额与预约口径

- `server_remaining` 保存本次服务器原始有效数值，不用本地值伪装上游响应。
- `effective_remaining` / 输出的 `reconciled_remaining` 是已扣除全部本地 ATTEMPT 的保守余额，尚未扣除未花预约。
- 每条 ATTEMPT 在发送前与预约减一原子提交，增加一次实际请求。OUTCOME 只结算响应，不再次计费。
- 有效同窗口时：`effective_remaining = min(server_remaining, previous.effective_remaining)`。previous 已包含当前及其他在途尝试的计费，响应不重复扣在途请求。
- `committed_in_progress` 是仍未花出的普通任务预约。新任务可用容量为余额减去这些预约一次；额度耗尽时禁止新准入。当前任务能否继续仍按原预算、真实余额、预约覆盖及授权判定。

例如已计费后本地余额 98、服务器 99，保留服务器 99，余额采用 98，未花预约 2 时
新准入容量为 96。下一次尝试把余额降为 97、未花预约降为 1；重复收到 99 只能取 97，
不会补回额度，也不再减去已花请求。服务器低于本地时采用服务器较小值。

窗口按同一工程绑定的凭据引用、API 桶和已验证 reset 定位。未知本地余额、缺失/非法
数值、limit 矛盾、过期/倒退或未经验证的窗口变化继续走各自失败路径。验证新窗口时
不跨窗口取最小值。401/403 仍是访问错误，不会被数字对账解锁。

## 证据、并发与分页

`BEGIN IMMEDIATE` 内原子保存 OUTCOME 和追加的 quota_window 对账行；后者保留服务器
值、选定余额及 predecessor，原前序提供本地值。控制事件输出固定原因
`RATE_LIMIT_BALANCE_MIN_APPLIED` 及服务器/本地/选定值，是非阻断提示。
无需修改查询、view、页大小或重新批准原任务。原预算还有请求且额度足够时，自动继续
下一未保存页；没有 paused receipt、额外 diagnostic 或人工 resume。

多请求已在途时，每个 ATTEMPT 先扣费；任一响应只与事务内最新余额合并。先后/乱序
响应的较大值不能回填同窗口余额。生产请求锁仍串行化发送与结算；恢复还使用原执行锁，
分页 attempt 引用和 checkpoint 链阻止重发保存页。测试含真实安装后两个恢复进程。

## 历史暂停：无需额外网络请求

`scopus-access reconcile --run-info <旧执行文件>` 使用保留的有效遥测和原始保存页，
追加 `RETAINED_MIN_RECONCILIATION`。`resume --execute-live` 对适用的旧数字暂停先自动
执行同样的本地修复。状态检查和导出仍只读，不自动写账本。

核对包括固定 manifest/policy/查询、项目凭据绑定、唯一计费 ATTEMPT 与 HTTP 200 OUTCOME、
页哈希、checkpoint 数量、遥测字段及最新桶/窗口。对账记录链接原前序并固定所用控制
证据哈希，不修改旧行、receipt、checkpoint、页、授权或预算。重复调用不重复追加。
历史遥测只保留在控制事件且账本归一化值为空时，也可以使用经核验的这些留存观测；
工具不会补造此前没保存的响应头。

只修复当前桶最新且仅因数值差异产生的旧暂停；不能用更早证据覆盖后来缺失头部、
权限错误、传输失败或窗口变化。请使用该最新有效数字暂停的 run-info；修复桶后，
其他原任务可在各自未过期授权及剩余预算内恢复。没有足够留存证据时明确拒绝本地修复。

原授权过期时仍可离线修正余额，但 `can_resume=false`，网络执行报授权过期。原单次
诊断已经用掉一请求时，只修正余额，预算仍为零，不能重发。真实零额度/覆盖不足和
原任务预算耗尽继续正常停止；它们不等同于数值不一致。

## 验证范围

`tests/test_quota_min.py` 验证高/低/相等/零余额、多个在途请求、乱序响应、重复高值、
并发事务、三页自动继续、保留原页/预算、追加且幂等的历史修复、篡改拒绝、窗口与授权
过期以及后来 401 不被旧证据解锁。`tests/test_installed_cli.py` 验证安装后的三页自动
继续及双进程历史修复/恢复不重复发送。自动测试只使用模拟凭据和 transport，并启用
socket/DNS 门禁。完整结果与制品身份见 [VALIDATION.md](VALIDATION.md)。

开发没有读取真实 Keychain、调用 API 或修改研究项目的历史账本。实网多页、当前凭据
权限及独立 401 根因仍须另行有界验收；本次不实现额外认证或完整参考文献分页。
